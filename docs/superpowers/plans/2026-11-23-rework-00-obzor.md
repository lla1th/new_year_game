# Переработка кода под `SCRIPT.md` — обзор и дорожная карта

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Привести код игры (этапы M0–M5 уже выполнены) в соответствие с новым сценарием `docs/SCRIPT.md`: Света, выбор имени шпица, разговоры, Мастерская Улитки, расширенные уровни L02–L08, головоломки P-02 (генератор), P-09 (наряд), тир, S-02a…S-08a.

**Architecture:** Движок уже data-driven (`LevelScript` + карты Tiled + `dialogs.json` + `ru.json` + чистая логика головоломок). Переработка идёт **снизу вверх**: сначала общие ID и данные (R0), затем новые системы (R1), затем уровни по одному (R2–R7), в конце сквозная проверка (R8). Тексты берутся из `SCRIPT.md` конвейером, карты — генератором из компактных описаний. Старые ID и ключи удаляются только в плане того уровня, который их использовал, поэтому игра остаётся проходимой после каждого этапа.

**Tech Stack:** Phaser 4, Vue 3, TypeScript, Vitest, Playwright (как в M0–M5).

**Spec:** `docs/SCRIPT.md` (главный: сюжет, реплики, контракты головоломок), `docs/DECISIONS.md` (записи 23.11), `docs/OPEN_QUESTIONS.md`; прежние планы `00-contracts.md`, `…-m0…m5` — исторические, контракты из них меняются только через R0.

## Global Constraints

- Правила `CLAUDE.md`: API Phaser/Vue/Vite/Vitest — после сверки через Context7; миграции БД не применяются (в проекте БД нет); коммиты на русском, Conventional Commits, после каждой задачи.
- Источник текстов — `docs/SCRIPT.md`; в коде реплик нет, только ключи (`ru.json`, `dialogs.json`, `talks.json`).
- Подстановка имени шпица — `{spitz}` в `SCRIPT.md`, внутри кода `{name.spitz}`; до выбора имени шпица зовут «Шпиц».
- Пустые поля автора (`[ЗАПОЛНИТЬ]`) **не блокируют** разработку: конвейер подставляет видимую заглушку `⟨заполнить: <ключ>⟩` и выводит отчёт; релиз блокируется командой `npm run texts:check` (R8).
- Инвентарь — 6 слотов (`INVENTORY_SIZE`); пик L02 = 6 предметов — новые предметы в L02 не добавлять.
- Контракты головоломок из `SCRIPT.md` (раскладки, порядки, решения) переносятся в код **точно**; изменение — только через правку `SCRIPT.md`.
- Мультиэкранные уровни: каждый экран — своя карта `public/assets/maps/<уровень>_<экран>.json`; переходы — `{ goto: { level, screen } }`.
- Побочные головоломки без штрафов и без тупиков; в диалоге-головоломке неверный ответ повторяет раунд.

## Review Focus

- Старое сохранение (`version: 1`) после обновления не должно ронять игру: «Продолжить» скрыто, «Начать» работает. Тест в R0.
- Сохранение с выбранным именем шпица восстанавливает имя во всех репликах и в таблице тира. Тест в R0/R2.
- Незаполненные поля автора никогда не роняют игру: ни пустая строка в кнопке имени, ни пустая таблица тира. Тесты в R0/R3.
- Диалог-головоломка Семёна: любая последовательность неверных ответов не блокирует игру; верные три раунда всегда проходят. Тест в R1.
- Пик инвентаря L02 (мандарин + 3 лампочки + насос + ключ склада = 6): ни один шаг уровня не требует 7-го слота. Тест в R3.

## Риски

- **Объём карт:** около 20 новых карт; генератор карт (R0) нужен, чтобы не писать Tiled-JSON вручную.
- **Графика:** все новые спрайты — заглушки (`ensureTexture`); реальные ассеты — по мере готовности, коду это не мешает.
- **Текстовый конвейер:** `SCRIPT.md` свободного формата; парсер ловит только строки таблиц с ключом в обратных кавычках — остальное (диалоги в одной ячейке, разговоры §12а) переносится вручную с проверкой тестом.
- **Старый код:** пока этап не выполнен, старый уровень остаётся рабочим; нельзя удалять общий код (например, `garland.ts`), пока его импортирует непереработанный уровень.
