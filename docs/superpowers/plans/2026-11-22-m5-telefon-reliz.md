# M5 «Телефон, полировка, релиз» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Удобная игра на телефоне и компьютере, проверенная сквозными тестами и тестерами, опубликованная на GitHub Pages.

**Architecture:** Классификация касаний — чистая функция; поведение ввода в Vue/Phaser берёт её результат. Сквозные тесты проходят игру через UI. Публикация — существующий workflow M0.

**Tech Stack:** Phaser 4, Vue 3, TypeScript, Vitest, Playwright.

**Spec:** `docs/UI_UX.md` §6–8, `docs/GAMEPLAY.md` §2, `docs/ACCEPTANCE_CRITERIA.md` (весь), `docs/TECHNICAL_SPECIFICATION.md` §11–13, `docs/OPEN_QUESTIONS.md` (T1).

**Предусловие:** M4 выполнен.

## Global Constraints

- Правила `CLAUDE.md`: сквозные тесты и проверки в браузере — **через Playwright MCP**; если он недоступен — спросить автора, можно ли использовать библиотеку Playwright напрямую. API — после сверки через Context7.
- Телефон — только горизонтальная ориентация; в вертикальной — экран «Поверните телефон».
- Долгий тап — ≥ 500 мс; сдвиг пальца > 12 px — это перетаскивание, а не тап.
- Минимальная зона касания — 44×44 CSS-пикселя.
- Перетаскиваемая иконка поднимается над пальцем на 60 px.
- Производительность: ≥ 30 кадров/с на среднем телефоне, 60 на компьютере; уровень грузится ≤ 5 с на 4G.
- **Публикация** — только после решения вопроса T1 (приватность GitHub Pages) автором. Без решения — не запускать деплой, спросить.
- Коммиты на русском, Conventional Commits, после каждой задачи.

## Review Focus

- Палец лёг на хотспот и начал двигаться (скролл-жест) — не должно срабатывать «использование». Тест в Task 1.
- Поворот телефона в вертикаль посреди диалога/головоломки — игра ставится на паузу под экраном «Поверните телефон» и продолжается с того же места. Проверка в Task 2.
- Системный жест «назад»/свайп браузера на iOS во время перетаскивания предмета — предмет возвращается в слот. Проверка в Task 2.
- Вырез экрана (notch) в горизонтальной ориентации перекрывает кнопки HUD — кнопки внутри безопасной зоны. Проверка в Task 2.
- Медленный интернет — экран загрузки показывает прогресс, а не пустой экран. Проверка в Task 3.

### Task 1: Касания: тап, долгий тап, перетаскивание

**Files:**
- Create: `src/ui/input/press.ts`
- Modify: `src/ui/Inventory.vue`, `src/game/scenes/LevelScene.ts`
- Test: `tests/ui/press.test.ts`

**Interfaces:**
- Produces:

```ts
export const LONG_PRESS_MS = 500;
export const DRAG_THRESHOLD_PX = 12;
export function classifyPress(durationMs: number, movedPx: number): 'tap' | 'long' | 'drag';
// movedPx > 12 → 'drag' (независимо от времени); иначе durationMs >= 500 → 'long'; иначе 'tap'
```

- [x] **Step 1: Тесты**

```ts
expect(classifyPress(100, 0)).toBe('tap');
expect(classifyPress(499, 12)).toBe('tap');
expect(classifyPress(500, 0)).toBe('long');
expect(classifyPress(100, 13)).toBe('drag');
expect(classifyPress(900, 40)).toBe('drag');
```

- [x] **Step 2–4:** FAIL → реализовать → PASS.
- [x] **Step 5: Интеграция**: в сцене на сенсорном вводе — `tap` = ЛКМ (идти/использовать; первый тап подсвечивает хотспот и сразу выполняет действие), `long` = осмотр, `drag` = ничего (не использовать хотспот); в инвентаре — `long` = осмотр предмета, `drag` = перетаскивание с иконкой выше пальца на 60 px; отмена касания (`pointercancel`) → предмет в слот. Отключить на canvas системные жесты (`touch-action: none`) и контекстное меню по долгому тапу.
- [x] **Step 6: Commit** — `feat: добавить управление касаниями`
