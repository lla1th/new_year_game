# TECHNICAL SPECIFICATION — техническая реализация

> APPROVED: Phaser 4 + Vue 3 + TypeScript; сцены — цельные картинки + Tiled для разметки; компьютер и телефон;
> GitHub Pages; статический сайт; тексты в файлах данных. Остальное — **[PROPOSED]**.
> Правило проекта: перед использованием API любой библиотеки сверяться с актуальной документацией через Context7.
> Пометка **(проверить)** — API, которое ещё не сверено с документацией.

## 1. Стек

| Компонент | Выбор | Примечание |
|---|---|---|
| Игровой движок | Phaser 4 (на 22.11.2026 актуальна 4.2.1 по Context7) | Рендер сцен, твины, ввод на canvas, звук |
| UI | Vue 3 + TypeScript | Меню, HUD, инвентарь, диалоги, настройки, открытка |
| Сборка | Vite | Шаблон Vue + TypeScript из `npm create @phaserjs/game@latest` (по документации Phaser поддерживает Vue) |
| Редактор разметки | Tiled | Только объектные слои поверх картинки |
| Тесты | Vitest (логика), Playwright (сквозные проверки) | См. раздел 12 |
| Хостинг | GitHub Pages через GitHub Actions | |

Без бэкенда, без аккаунтов, без внешних запросов во время игры.

## 2. Архитектура

```
┌───────────── Vue (DOM поверх canvas) ─────────────┐
│ MainMenu  Hud  Inventory  DialogBox  Settings  Card│
└───────────────┬───────────────────────────────────┘
                │ EventBus (типизированные события)
┌───────────────┴───── Phaser 4 ────────────────────┐
│ BootScene → PreloadScene → LevelScene(Lxx)         │
│                     ↕ PuzzleScene(P-xx) поверх      │
│                     ↕ TransitionScene               │
└───────────────┬───────────────────────────────────┘
                │
        GameState (единый стор: уровень, флаги, инвентарь, детали, настройки)
                │
           SaveService (localStorage)
```

- **GameState** — единственный источник правды (простой реактивный стор Vue `reactive()` или Pinia — выбрать
  при реализации, Pinia только если понадобится). Phaser читает и меняет состояние через методы стора.
- **EventBus** — обмен событиями между Vue и Phaser. Можно использовать `game.events` Phaser (подтверждено в
  документации Phaser 4 как глобальная шина) или отдельный `EventEmitter`.
- Логика головоломок — **чистые TypeScript-модули без Phaser** (`src/puzzles/logic/*.ts`): состояние, действие →
  новое состояние, проверка решения. Сцены головоломок только рисуют и передают клики. Это позволяет тестировать
  логику юнит-тестами.

### Ключевые события EventBus

| Событие | Направление | Данные |
|---|---|---|
| `dialog:start` / `dialog:end` | Phaser → Vue / Vue → Phaser | `dialogId` |
| `item:drop` | Vue → Phaser | `itemId`, `x`, `y` (в координатах игры 1920×1080) |
| `item:combine` | Vue → логика | `itemA`, `itemB` |
| `hint:request` | Vue → логика | — |
| `say` | Phaser → Vue | `speaker`, `textKey` |
| `scene:ready` | Phaser → Vue | `levelId` |
| `puzzle:open` / `puzzle:close` | Phaser → Vue | `puzzleId` |

**Перетаскивание предмета из Vue на сцену:** Vue отслеживает pointer-события, при отпускании переводит
координаты экрана в координаты игры (с учётом масштаба canvas) и отправляет `item:drop`. Phaser определяет
хотспот **собственной проверкой точки в полигоне** по данным Tiled — без зависимости от системы ввода Phaser.

## 4. Сцены и разметка Tiled

**Подход:** фон — одна картинка; Tiled-карта используется как разметка. В Tiled создаётся карта размером
1920×1080 (для мира 1 — тоже в координатах 1920×1080, хотя картинка 480×270 ×4), картинка добавляется слоем-изображением
только для наглядности разметки.

**Загрузка:** экспорт JSON из Tiled грузится как обычный JSON, игра читает только объектные слои.
Тайловые слои не используются. (Phaser умеет грузить Tiled-карты, но для объектных слоёв достаточно прочитать JSON.)

**Обязательные объектные слои:**

| Слой | Объекты | Свойства |
|---|---|---|
| `walkable` | Полигоны проходимой области (можно несколько) | — |
| `blockers` | Полигоны-дыры внутри проходимой области (мебель) | — |
| `hotspots` | Полигоны/прямоугольники | см. `INTERACTION_SYSTEM.md` §1 |
| `points` | Точки `spawn`, `spitz_spawn`, точки кат-сцен | `name` |
| `sprites` | Точки размещения отдельных спрайтов (персонажи, меняющиеся предметы) | `texture`, `depthY` |

**Свойства карты:** `levelId`, `background` (путь к картинке), `pixelArt` (bool), `footsteps` (`snow`/`floor`/`metal`),
`music`.

Для уровня с несколькими экранами (L03) — отдельная карта на экран: `L03_square.json`, `L03_floor1.json`, `L03_top.json`.

## 5. Отрисовка

- Базовое разрешение **1920×1080**, режим масштабирования «вписать с сохранением пропорций» (Phaser Scale Manager — **проверить** названия режимов в Phaser 4).
- **Пиксель-арт**: фоны 480×270, увеличение ×4 без сглаживания. Сглаживание должно отключаться **для конкретных
  текстур** мира 1, а не глобально, т.к. другие миры — гладкие (**проверить** API фильтрации текстур в Phaser 4).
- **Глубина (z-порядок)**: спрайты сортируются по Y нижней точки (`depthY`), чтобы Ксюша заходила «за» объекты.
  Объекты переднего плана, за которые она заходит, — отдельные спрайты.
- **Переход «перерисовка кистью»**: TransitionScene рендерит старый и новый кадры и раскрывает новый через маску из
  анимированных мазков кисти. В Phaser 4 маски реализуются фильтром `Mask` (подтверждено в руководстве по миграции
  v3→v4; детали API — **проверить**). Запасной вариант, если маска окажется сложной: последовательность из 8–12
  кадров-мазков поверх картинки нового мира.

## 6. Ходьба и поиск пути

- Проходимая область (`walkable` минус `blockers`) растеризуется в сетку с шагом 16 px (120×68 клеток).
- A* с 8 направлениями, затем сглаживание пути проверкой прямой видимости между точками.
- Клик вне области → ближайшая проходимая клетка.
- Направление позы Ксюши выбирается по вектору движения (4 диагонали).
- Своя реализация (~150 строк), без внешних библиотек.

## 7. Скрипты уровней

Скрипт уровня `levels/Lxx.ts` описывает реакции декларативно, тексты — только ключами:

```ts
// иллюстрация структуры данных, не финальный API
{
  hotspot: 'sofa',
  onUse: [{ say: 'ksyusha', key: 'l01.sofa.use' }],
  onItem: {
    ITEM_MANDARIN: [{ sfx: 'sfx_spitz_sneeze' }, { say: 'spitz', key: 'l01.sofa.mandarin' }, { say: 'ksyusha', key: 'l01.sofa.mandarin2' }],
    ITEM_SAUSAGE:  [{ removeItem: 'ITEM_SAUSAGE' }, { anim: 'spitz_out' }, { setFlag: 'L01_SPITZ_FREED' }, { dialog: 'l01_intro' }, { setFlag: 'L01_PORTAL_OPEN' }],
  },
}
```

Набор шагов: `say`, `dialog`, `giveItem`, `removeItem`, `setFlag`, `anim`, `sfx`, `walkTo`, `openPuzzle`,
`goto` (уровень/экран), `cutscene`, `wait`. Больше ничего не нужно.

## 8. Тексты и данные

- **Все строки** — в `public/data/texts/ru.json`, плоский словарь `"ключ": "текст"`. Код не содержит русского текста.
- Подстановки: `{name.spitz}` → имя из `characters.json`, чтобы имя шпица/кошечки/улитки менялось в одном месте.
- Наборы случайных реплик: ключи `common.wrongItem.1…N`, N определяется по количеству ключей.
- Если ключа нет — в игре показывается `⟨ключ⟩` и в консоль пишется предупреждение (видно при тестировании).

## 9. Сохранение

- `localStorage`, ключ `onye-save-v1`; настройки — отдельно, ключ `onye-settings-v1`.
- Формат:

```json
{
  "version": 1,
  "levelId": "L02",
  "screenId": null,
  "flags": { "L01_SPITZ_FREED": true },
  "inventory": ["ITEM_MANDARIN"],
  "parts": [],
  "completed": false,
  "savedAt": "2026-12-31T20:00:00Z"
}
```

- Запись — в начале уровня (после загрузки) и сразу после решения каждой головоломки.
- Состояние частично собранной головоломки **не сохраняется**: при загрузке головоломка начинается с начального состояния.
- Если сохранение повреждено или версии не совпадают — игнорировать его и скрыть «Продолжить».

## 10. Загрузка ресурсов

- `PreloadScene` грузит общие ресурсы (UI, Ксюша/шпиц текущего мира, звуки интерфейса).
- Ресурсы уровня грузятся при входе в уровень с экраном загрузки (снежинка + процент).
- Ресурсы следующего уровня догружаются в фоне во время текущего **(проверить** поддержку фоновой загрузки в загрузчике Phaser 4).
- Бюджет: весь билд ≤ 60 МБ, один уровень ≤ 8 МБ.

## 11. Производительность

- Цель: 60 кадров/с на компьютере, ≥ 30 на среднем телефоне 2022 года.
- Текстуры не больше 2048×2048 (фоны 1920×1080 — отдельные картинки, не атласы).
- Мелкие спрайты и иконки — в атласах по миру.
- Фоны — WebP (качество 85), прозрачные спрайты — PNG или WebP с альфой.

## 12. Тестирование

- **Юнит-тесты (Vitest)** для `puzzles/logic`: все сценарии тестирования из `PUZZLE_SPECIFICATIONS.md`,
  включая решаемость P-04/P-05 и 100 перемешиваний P-08.
- **Сквозные тесты**: по правилу проекта — через Playwright MCP; если он недоступен — спросить у автора,
  можно ли использовать библиотеку Playwright напрямую. Минимум: запуск, проход L01 кликами, сохранение и «Продолжить».
- Отладочный режим `?debug=1`: показ полигонов Tiled, переход на любой уровень, выдача предметов и флагов.

## 13. Публикация

- GitHub Actions: сборка Vite → публикация в GitHub Pages.
- `base` в конфиге Vite = `/<имя-репозитория>/`.
- Важно: сайт GitHub Pages публичен для всех, у кого есть ссылка. На бесплатном аккаунте GitHub Pages, по моим
  данным, публикуется только из публичного репозитория (**проверить** перед публикацией) — решение в `OPEN_QUESTIONS.md`.
