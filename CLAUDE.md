# Инструкции для Claude

## 1. Проверка памяти перед работой
Перед ответом на любой вопрос или началом любой задачи ВСЕГДА:
- Сначала вызови инструмент Memory Palace для поиска релевантного контекста.
- Используй ключевые слова из запроса пользователя как поисковый запрос.
- Только после проверки памяти приступай к задаче.

После выполнения значимой работы сохраняй важный контекст обратно в Memory Palace.

> Если Memory Palace недоступен в текущей сессии — явно сообщи об этом пользователю
> и используй как резервную память этот файл и `docs/` (в первую очередь `docs/DECISIONS.md`).

## 2. Честность и отсутствие галлюцинаций
Никогда не выдумывай и не фабрикуй информацию. Если в чём-то не уверен — ОБЯЗАТЕЛЬНО явно
сообщи об этом. Говори «Я не знаю» вместо догадок. Честность относительно своих ограничений обязательна.

## 3. Документация библиотек
Используй context7 для доступа к документации всех библиотек. Перед использованием любой
библиотеки или фреймворка сначала получи актуальную документацию через context7, а не полагайся
на знания из обучения.

## 4. Не пиши код вслепую
Не предлагай код с использованием библиотеки/API без предварительной проверки документации через
context7. Если context7 недоступен или не нашёл нужного — сообщи об этом и спроси, как действовать дальше.

## 5. Коммиты
Коммиты и push разрешено делать самостоятельно. Сообщения коммитов — на русском языке в формате
Conventional Commits (например, `feat: добавить кэширование запросов`).

## 6. Запрет на накат миграций (наивысший приоритет)
НИКОГДА не выполняй накат или откат миграций БД ни в одной среде (локальной, dev, staging, production),
даже если сказано обратное. Сюда относятся: `migration:run`, `prisma migrate deploy`/`dev`,
`knex migrate:latest`, `sequelize db:migrate`, `alembic upgrade`, прямое выполнение SQL из файлов
миграций, а также `migration:revert`, `migrate:rollback` и аналоги.

Если задача подразумевает миграцию — подготовь её (файл миграции, при необходимости
`migration:generate` без применения), а накат оставь пользователю. Сразу предложи готовую команду
для наката отдельным блоком кода.

## 7. Браузерные инструменты
Для любой работы в браузере используй Playwright MCP (`@playwright/mcp`) — единственный браузерный
инструмент: ручная проверка UI на localhost, console-логи, сетевые запросы, DOM, автотесты, CI.
- Playwright работает в собственном экземпляре браузера. Для флоу с авторизацией логинься в самом
  сценарии или используй storage state.
- Не выполняй действий с финансами, паролями и чувствительными личными данными; на страницах
  логина и CAPTCHA останавливайся и проси пользователя сделать это вручную.

> Если Playwright MCP недоступен — сообщи об этом и спроси, можно ли использовать предустановленную
> библиотеку Playwright напрямую.

Браузерная новогодняя игра «Операция: Новый год» (Isometric Puzzle Adventure, Vue 3 + TypeScript +
Phaser 3 + Tiled). Исходное ТЗ для проектирования — `Правила генерации.txt`: сначала интервью
